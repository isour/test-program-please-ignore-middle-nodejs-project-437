Главная страница и промо-блоки

На корневом адресе магазина — не каталог, а главная страница с промо-блоками. Каждый блок это заголовок, текст и товар, на страницу которого блок ведёт. Шаг небольшой, но в нём два содержательных решения.

Промо-блоки хранятся в базе, а не в вёрстке. Контент, который меняется без релиза, — это данные. Тексты в разметке пришлось бы править кодом и выкладывать заново, а витрину магазина меняют каждую неделю.

Товар приходит внутри блока. Ответ GET /api/promos содержит товар целиком, а не только его идентификатор. Иначе фронтенд на каждый блок делал бы отдельный запрос за товаром — это классическая проблема N+1: одна страница вместо одного запроса делает столько, сколько на ней блоков.

Требования

  • GET /api/promos отдаёт массив блоков: { id, title, text, product }, где product — товар в том же виде, что в каталоге.
  • Промо-блоки лежат в базе и заливаются вместе с данными каталога.
  • Блоков не меньше двух, каждый — на доступный товар.
  • Один товар не участвует в двух блоках. Проще всего гарантировать это уникальным индексом по идентификатору товара в таблице блоков — заодно заливка становится идемпотентной.
  • Пустой список — 200 и []: главная должна оставаться рабочей.

Задачи

  1. Добавьте таблицу промо-блоков: заголовок, текст, ссылка на товар, уникальность по товару.

  2. Дополните заливку данных: минимум два блока на доступные товары.

  3. Реализуйте GET /api/promos одним запросом с соединением таблиц — товар отдавайте вложенным объектом. Захардкоженный список промо-блоков после этого удалите.

  4. Напишите тест на API: блоков не меньше двух, у каждого есть вложенный товар со всеми полями, все товары доступны.

  5. Откройте главную: блоки видны, клик по блоку ведёт на страницу своего товара.

    curl -s http://localhost:8080/api/promos | head -c 200

Подсказки

  • Собирать вложенный объект из плоской строки результата удобно в одном месте — там же, где вы приводите типы для остальных ответов. Иначе price.amount окажется строкой только в промо-блоках, и главная сломается, а каталог нет.
  • Заливка блоков должна выполняться после товаров: блок ссылается на товар.
  • Не отдавайте недоступные товары в блоках: фронтенд ведёт с блока на карточку, а купить оттуда ничего нельзя — сценарий обрывается.

Результат шага

Главная страница показывает промо-блоки из вашей базы, каждый ведёт на свой товар, и всё это одним запросом к API.
